# ADR-0003: Technology stack

- Status: Accepted (2026-09-25)
- Date: 2026-09-24

## Context

PRD §9 recommends a stack. This ADR confirms it and records where we deviate or narrow a choice. The stack must run identically on SaaS, private cloud and a single on-prem server, and every component must have a licence that allows redistribution in an on-prem installer.

## Implementation notes (Phase 0, 2026-09-25)

- Workspace packages export a custom `@manuling/source` condition that points to `src/*.ts`. Typecheck, tests and dev mode run from source without a prior build, and production uses `dist/`.
- API schemas that appear in OpenAPI must import `z` from `apps/core/src/openapi/zod.ts`. Zod 4 attaches methods per instance, so the OpenAPI extension must load first.

## Consequences

- Every runtime dependency is permissively licensed or runs as an unmodified, separate network service, so the on-prem distribution is safe (legal review still required before GA).
- A single-server on-prem footprint of about 16 vCPU / 32 GB is realistic.

## Alternatives considered

- Prisma: good DX, but RLS needs per-transaction session variables and interactive transactions, which it handles awkwardly.
- NATS JetStream as the primary broker: lighter, but a weaker ecosystem for CDC and analytics sinks. Running two brokers doubles the test matrix. NATS may still appear at the edge.
- Flutter for mobile: rejected so the whole stack stays in TypeScript and shares Zod schemas and i18n bundles.
